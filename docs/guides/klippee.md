# Klippee configuration sync

Klippee configuration sync is built into hlab in Go. Use `hlab klippee` from
the configuration folder, or `hlab printer klippee` with a saved printer.
Neither path requires Python, curl, or a separately installed Klippee command.

Build and install hlab from this checkout using `make install` on macOS/Linux
or `.\build.ps1 install` on Windows. Release binaries must include the
`hlab klippee` command; older releases do not.

## Connect a desktop folder

Create a folder, open a terminal there, then run the private setup command
generated by Klippee's **Desktop IDE** integration. It sets
`KLIPPEE_BASE_URL`, `KLIPPEE_REPOSITORY_ID`, and `KLIPPEE_TOKEN`, then runs:

```sh
hlab klippee init --desktop --apply-current
hlab klippee target
hlab klippee check --diff
```

Credentials stay in `.klippee/config.json`. Existing desktop connection files
work without conversion. hlab refuses tracked or linked credentials and
requires Git to ignore workspace state. POSIX connection files must belong to
the current user and have no group or other permissions.

```sh
hlab klippee capture --note "Edited in VS Code"
hlab klippee apply
hlab klippee variables set beacon_serial /dev/serial/by-id/usb-Beacon_...
hlab klippee variables doctor
hlab klippee recover
hlab klippee recover local:manual-...
```

Use `--workspace PATH` to select a folder explicitly. A saved printer's
`klippee.workspace` uses exactly that folder's desktop connection, with no
global connection fallback. Its target, check, apply, capture, and variable
commands call the same native implementation.

Apply identifies the target, shows changes, requires confirmation, refetches
the desired snapshot, and backs up files before replacement. `--yes` records
an explicit decision; `--if-clean` instead requires a valid unchanged saved
baseline. A changed target or local file during review stops installation.
Desktop apply never advances the physical printer's applied state.

Capture follows `printer.cfg` includes, excludes local variables, credentials,
runtime state, backups, and unreferenced files, and sends the saved base
revision to detect cloud conflicts. Capture follows safe linked includes such
as Klipper add-on directories. Apply and recovery refuse to write through
configuration links. Config paths must be
portable across Windows, macOS, and Linux (no reserved device names, trailing
dots/spaces, or combining characters).

Local variable values render `${KLIPPEE:name}` placeholders without sending the
values to Klippee. Capture restores known template lines. If a rendered line
was edited, restore its placeholder explicitly before capture; hlab refuses to
upload that line with a potentially private value.

## Physical printers and compatibility

`hlab klippee init --printer` supports native configuration sync when hlab is
installed on the printer. Use `KLIPPEE_CONFIG_DIR` to choose its configuration
folder and `KLIPPEE_STATE_DIR` to choose its connection directory. Physical
apply confirms the exact template snapshot with Klippee after installation.
`hlab klippee --connection PATH` explicitly selects a connection file.

Install the release binary on the printer under a stable path such as
`~/.local/bin/hlab`. An existing printer connection in `~/.klippee/config.json`
or the older `~/.klippee/config` works as-is. Check the connection before
switching an existing service:

```sh
hlab klippee target
hlab klippee check --diff
hlab klippee install-moonraker
hlab klippee install-timer
```

Run the Moonraker installer while Klipper is idle and the old agent has no
operation running. It updates the managed service, verifies that the native
agent answers Moonraker, and restores the previous service on activation
failure. If it adds macros, restart Klipper when ready to make them visible.
The timer runs read-only checks.

`hlab klippee upload-diagnostics` creates a private support bundle. Use
`--previous` for a rotated log. `hlab klippee query-box-reset-reason` is a
read-only query for the supported QIDI Box firmware while Klipper is shut down.
Dashboard macros and the Moonraker methods used by `hlab printer klippee`
retain their names and operation IDs. The compatibility commands for
existing Python agents remain available during rollout.

To update the native agent, replace hlab at the same path with a verified
release, then run `hlab klippee install-moonraker` on the idle printer.

An explicit custom `defaults.klippee.executable` still invokes that executable
for existing integrations. An omitted value or the historical default
`klippee` uses native sync.
